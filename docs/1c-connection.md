# Подключение реальной базы 1С

Инструкция для поставщика и его программиста 1С: как подготовить базу и что указать в приложении, чтобы витрина брала из 1С номенклатуру, цены и остатки, а заявки становились документами «Заказ клиента».

Обмен идёт через **стандартный интерфейс OData** платформы «1С:Предприятие 8.3». Он включается при публикации базы и настройкой состава. Программировать в самой конфигурации не нужно.

---

## Готовность: прочитайте до подключения

Обмен написан по правилам стандартного интерфейса OData и типовой «1С:Управление торговлей 11» / ERP 2: виртуальные таблицы со скобками, GUID-ссылки, обязательные реквизиты заказа, отдельное проведение. Проверен он на **строгом эмуляторе 1С** (`mock-1c`), который отклоняет всё, что отклонила бы настоящая база. **На настоящей базе обмен ещё не запускался** — первое подключение пройдите по разделу 7 на тестовой копии базы. Что осталось проверить — в последнем разделе.

---

## 1. Что нужно от базы

| | Требование |
|---|---|
| Платформа | 1С:Предприятие 8.3, рекомендуется 8.3.14 и новее — ответы в JSON |
| Конфигурации | «Управление торговлей 11.4 / 11.5», «Комплексная автоматизация 2.4 / 2.5», «ERP Управление предприятием 2.4 / 2.5». Для УНФ и «Розницы» другие имена объектов, см. раздел 5 |
| Публикация | веб-сервер Apache 2.4 или IIS с модулем расширения веб-сервера 1С, доступ снаружи **только по HTTPS** |
| Пользователь | отдельный служебный пользователь для обмена, без интерактивного входа |

---

## 2. Публикация базы с OData

1. Установите модуль расширения веб-сервера (компонент «Модули расширения веб-сервера» в установщике платформы).
2. В Конфигураторе: **Администрирование → Публикация на веб-сервере**.
   - Имя публикации — латиницей, например `trade`.
   - Отметьте **«Публиковать стандартный интерфейс OData»**.
   - Остальное, что не нужно снаружи (тонкий клиент, веб-клиент, HTTP-сервисы), лучше не публиковать: чем меньше открыто, тем меньше риск.
3. Настройте HTTPS с доверенным сертификатом, например Let's Encrypt. Самоподписанный сертификат наш сервер не примет.
4. Ограничьте доступ к публикации по IP: разрешите только адрес сервера приложения. Его сообщит администратор стенда.

После публикации интерфейс доступен по адресу:

```
https://<домен>/<публикация>/odata/standard.odata/
```

---

## 3. Состав стандартного интерфейса OData

По умолчанию стандартный интерфейс OData пуст: объекты нужно включить явно. В типовых конфигурациях это делается обработкой **«Настройка стандартного интерфейса OData»** (в УТ 11 и ERP: *Администрирование → Синхронизация данных*). Программно — методом платформы `УстановитьСоставСтандартногоИнтерфейсаOData()`.

Включите объекты для своей версии:

| Что берём | УТ 11.4, КА 2.4, ERP 2.4 | УТ 11.5, КА 2.5, ERP 2.5 |
|---|---|---|
| Номенклатура | Справочник «Номенклатура» | то же |
| Единицы и упаковки | Справочник «Упаковки единицы измерения» | то же |
| Виды цен | Справочник «Виды цен» | то же |
| Цены | Регистр сведений «Цены номенклатуры» | Регистр сведений «Цены номенклатуры 25» |
| Остаток на складе | Регистр накопления «Товары на складах» | то же |
| Свободный остаток (за вычетом резервов) | Регистр накопления «Свободные остатки» | Регистр сведений «Распределение запасов» (с 11.5.7 / 2.5.7) |
| Склады, организации | Справочники «Склады», «Организации» | то же |
| Клиенты | Справочники «Партнёры», «Контрагенты», «Соглашения с клиентами» | то же |
| Заказы | Документ «Заказ клиента» | то же |

Проверка: откройте в браузере

```
https://<домен>/<публикация>/odata/standard.odata/$metadata
```

и войдите служебным пользователем. В ответе должны быть все объекты из таблицы.

## 4. Служебный пользователь

Создайте пользователя, например `Обмен_MAX`, с минимальными правами:

- роль **«Удалённый доступ OData»** (`УдаленныйДоступOData`);
- **чтение** номенклатуры, упаковок, видов цен, складов, организаций, партнёров, контрагентов, соглашений, регистров цен и остатков;
- **добавление, изменение и проведение** документа «Заказ клиента»;
- без административных прав и без права интерактивного входа.

Пароль — длинный и случайный. Его вы укажете в приложении, в самой базе он больше нигде не используется.

## 5. Как обмен ложится на объекты 1С

| Действие в приложении | Что происходит в 1С |
|---|---|
| Создание витрины, «Синхронизировать», фоновая сверка раз в минуту | чтение номенклатуры (без групп и помеченных на удаление), цен выбранного вида (`SliceLast(Condition=…)`) и свободного остатка выбранного склада (`Balance(Condition=…)`, ресурс «В наличии»). Позиция, которой больше нет в 1С, скрывается из витрины и возвращается, когда появится снова |
| Клиент оформил заявку | создаётся «Заказ клиента» с организацией, складом, валютой, партнёром, контрагентом и соглашением из настроек витрины. Номер заявки — в реквизите «Номер по данным клиента»: по нему повторная выгрузка находит уже созданный документ. Дальше — по выбору поставщика, как в «Моби-С»: **по умолчанию** заказ «На согласовании» и не проводится (в УТ такой заказ не резервирует — до подтверждения резерв держит приложение); **«Резервировать в 1С сразу»** — заказ в статусе «К выполнению» и проведён |
| Менеджер подтвердил заявку | количества правятся, заказ переводится в «К выполнению» и проводится (`/Post`) — товар резервируется |
| Поставщик перенёс доставку | меняется «Дата отгрузки» |
| Отказ поставщика или отмена клиентом | проведение снимается (`/Unpost`), заказ помечается на удаление |
| Приёмка с расхождениями | расхождения дописываются в комментарий заказа. «Корректировку реализации» в УТ оформляют по реализации, а не по заказу, — её делает учётчик |

Контрагента магазина выбирают сразу, когда одобряют его просьбу о подключении: в шторке **«Подключить клиента»** у витрины на 1С — список контрагентов базы. Поменять — в карточке клиента: **«Клиенты» → клиент → «Контрагент в 1С»**. Без выбора магазин оформляется контрагентом по умолчанию из настроек витрины — так же и магазин, пришедший по приглашению, пока ему не выберут контрагента в карточке. Партнёр берётся из карточки контрагента.

Имена объектов OData — настройка витрины: версия конфигурации выбирается при подключении.

| Объект | УТ 11.4 / КА 2.4 / ERP 2.4 | УТ 11.5 / КА 2.5 / ERP 2.5 до 11.5.7 | УТ 11.5.7+ / ERP 2.5.7+ |
|---|---|---|---|
| Номенклатура | `Catalog_Номенклатура` | то же | то же |
| Цены | `InformationRegister_ЦеныНоменклатуры/SliceLast()` | `InformationRegister_ЦеныНоменклатуры25/SliceLast()` | то же |
| Свободный остаток | `AccumulationRegister_СвободныеОстатки/Balance()` | то же | `InformationRegister_РаспределениеЗапасов`, строки по складу |
| Заказ | `Document_ЗаказКлиента` | то же | то же |

Для УНФ и «Розницы» имена другие (например, в УНФ заказ — `Document_ЗаказПокупателя`). Сервер умеет принять свои имена поверх шаблона (`onec_settings.objects` витрины), но в интерфейсе такого поля пока нет.

## 6. Подключение в приложении

1. Владелец создаёт витрину, режим «Со склада», и открывает **«Витрины» → «Настройки» → «Подключить 1С» → «Своя база 1С»**.
2. **Адрес публикации** — `https://<домен>/<публикация>`. Часть `/odata/standard.odata/` приложение добавит само. Адрес — публичный и конечный: внутренние адреса (`10.…`, `192.168.…`, `localhost`) и перенаправления приложение не принимает, чтобы через адрес базы нельзя было обратиться во внутреннюю сеть сервера.
3. **Пользователь и пароль** служебного пользователя 1С. Пароль хранится на сервере зашифрованным и обратно в настройки не приходит.
4. **Конфигурация** — версия УТ, КА или ERP: от неё зависят имена регистров.
5. **«Проверить подключение»** — приложение прочитает из базы списки и покажет их. Выберите **организацию, склад, вид цен, валюту, контрагента по умолчанию** и, если ведёте, **соглашение**.
6. Решите, **резервировать ли в 1С сразу** (см. раздел 5), и сохраните. Позиции, цены и остатки загрузятся сразу; в журнале «Обмен с 1С» появится запись.

---

## 7. Проверка после подключения

1. **Номенклатура.** В витрине те же позиции, что в 1С; групп и помеченных на удаление среди них нет.
2. **Цены** совпадают с выбранным видом цен в 1С.
3. **Остатки** совпадают со свободным остатком выбранного склада в отчёте «Остатки и доступность товаров».
4. **Заявка.** Оформите тестовую заявку с клиентского аккаунта. В 1С появится «Заказ клиента», в реквизите «Номер по данным клиента» — номер заявки.
5. **Подтверждение.** Подтвердите заявку с изменённым количеством. В 1С заказ проведён, количества новые.
6. **Отмена.** Отмените вторую тестовую заявку. В 1С заказ не проведён и помечен на удаление.

---

## 8. Безопасность на стороне поставщика

- Публикация доступна только по HTTPS и только с IP сервера приложения.
- Служебный пользователь не имеет административных прав. Его пароль не используется больше нигде.
- Опубликован только стандартный интерфейс OData. Тонкий и веб-клиент через эту публикацию не открыты.
- Журнал регистрации 1С фиксирует все изменения, сделанные служебным пользователем, — по нему видно, что пришло из приложения.

## Что сделано по сверке с 1С и что осталось проверить

Сверка с документацией платформы и типовых конфигураций показала, что прежний клиент и эмулятор принимали запросы, которые настоящая база отклонит. Исправлено:

1. **Поля подключения** — адрес, пользователь и пароль своей базы; пароль шифруется на сервере ключом из секрета стенда и наружу не отдаётся.
2. **Виртуальные таблицы** — со скобками и отбором в `Condition`: `SliceLast(Condition='ВидЦены_Key eq guid'…'')`, `Balance(Condition='Склад_Key eq guid'…'')`.
3. **Ссылки** — только GUID: у позиций хранится `Ref_Key`, строки заказа ссылаются на `Номенклатура_Key`, магазины сопоставляются с контрагентами.
4. **Обязательные реквизиты заказа** — организация, партнёр, контрагент, соглашение, склад, валюта, хозяйственная операция, дата. Не выбраны — заказ встаёт в очередь с объяснением, какого реквизита не хватает.
5. **Остаток** — ресурс «В наличии» регистра свободных остатков по складу.
6. **Справочник** — `$select` и `$filter`, без групп (`IsFolder`) и помеченных на удаление (`DeletionMark`); единица — ссылкой на «Упаковки единицы измерения». Кратности в типовой УТ нет — её задаёт поставщик в приложении.
7. **Статусы** — «На согласовании» и «К выполнению»; проведение — отдельным `/Post`; резерв — по выбору поставщика.
8. **Внешний ключ** — стандартный реквизит «Номер по данным клиента»; строки в `$filter` экранируются удвоением кавычки.
9. **Расхождения приёмки** — комментарием к заказу, корректировку делает учётчик.
10. **Имена объектов** — настройка витрины, а не переменные окружения.
11. **Строгий эмулятор** — требует скобки и GUID, проверяет поля в `$select` и `$filter`, обязательные реквизиты при проведении, имя пользователя; «На согласовании» не резервирует.

Осталось проверить на настоящей базе:

- **УТ 11.5.7+ / ERP 2.5.7+:** регистр «Распределение запасов» и имя его ресурса — по `$metadata` своей базы. Шаблон приложения — предположение.
- **Списки справочников** отбираются только по пометке удаления: группы складов и контрагентов, если они есть, попадут в список выбора.
- **Параметры виртуальных таблиц.** Кавычки внутри `Condition` приложение передаёт так, как в примерах документации платформы. Если база ответит ошибкой разбора, это первое, что стоит сверить.
- **Реквизиты табличной части** заказа: `Количество`, `КоличествоУпаковок`, `Цена`, `Сумма`. В некоторых версиях обязательны `Упаковка_Key` и ставка НДС.
