# Руководство разработчика

Витрина поставщика в MAX: мини-приложение и бот, через которые магазины заказывают у поставщика, а заявка сразу становится «Заказом клиента» в 1С. Хакатон Минобрнауки × MAX, трек «Эффективный бизнес».

- Стенд — https://14-bit-max.ru, бот — @t7_hakaton_max_bot.
- Запуск, переменные окружения и пошаговая проверка — [README.md](../README.md).
- Правила продукта — [business_logic.md](../business_logic.md), замысел и решения — [product/concept.md](product/concept.md).
- Подключение настоящей 1С — [1c-connection.md](1c-connection.md).

## Устройство

`docker compose`, семь контейнеров:

| Сервис | Где | Что делает |
|---|---|---|
| `caddy` | `Caddyfile` | TLS; `/api/*` → api, `/webhook*` и `/health` → bot, `/1c*` → эмулятор 1С, остальное → miniapp |
| `api` | `services/api` | FastAPI + SQLAlchemy async + Alembic, вся бизнес-логика |
| `bot` | `services/bot-service` | вебхук MAX, уведомления с кнопками, приглашения; не больше 30 запросов в секунду к API MAX |
| `mock-1c` | `services/mock-1c` | строгий эмулятор OData «Управления торговлей 11» и кабинет тестовых баз `/1c` |
| `miniapp` | `services/miniapp` | React 19 + Vite + HeroUI v3 + Tailwind v4 |
| `db`, `s3` | — | Postgres 16 и MinIO: фото, логотипы, снимки приёмки |

**API (`services/api/app`)**
- `auth.py` — личность только из подписи MAX (`X-Max-Init-Data`, проверка в `shared/webapp_auth.py`, подпись действует сутки). Роль — заголовком `X-Active-Role` среди тех, что есть у человека.
- `models.py` — сущности, `schemas.py` — формы запросов и ответов, `routers/` — эндпоинты.
- `onec/` — обмен с 1С по OData настоящей УТ 11: клиент, настройки под версии конфигураций, выгрузка заказа и очередь повторов. `stock.py` — сверка остатков, `inventory.py` — резерв.
- `messaging.py`, `notify.py`, `mutes.py` — уведомления в ленту и в MAX. `live.py` — сокет «что изменилось».
- `lifecycle.py` и `reminders.py` — фоновый проход: «в производстве» после отсечки, вопрос о неотмеченной отгрузке, напоминания об отсечке.
- `testbots.py` — тестовые боты, см. ниже. `seed.py` — демо-данные.
- Миграции применяются при старте (`app/migrate.py`). Откат — `alembic downgrade` в контейнере, пока файл миграции ещё в образе, и только потом удалять файл.

**Мини-приложение (`services/miniapp/src`)**
- `App.tsx` — маршруты по роли. `lib/nav.ts` — стек экранов в памяти: веб-версия MAX открывает приложение во фрейме с общей историей браузера.
- `lib/api.ts` — клиент с подписью и ролью, `lib/live.ts` — сокет, `lib/bridge.ts` — обёртка `window.WebApp`, `lib/cart.tsx` — корзины по витринам.
- Цвета — только токены из `theme/max.css`: три гаммы меняют основной и вторичный цвет. Типографика — классы `t-header`, `t-title`, `t-body`, `t-desc`, `t-label`.
- `components/BottomBar.tsx` сообщает свою высоту переменной `--bottom-bar-h`, и отступ экрана снизу берётся из неё, а не числом.
- Номер экрана в углу — `lib/screens.ts`: новый экран или шторка — строка в каталоге.

## Предметная область

- **Роли:** `owner` — владелец поставщика, `manager`, `client` — владелец магазина, `worker` — работник магазина. Аккаунт — либо поставщик, либо магазин: приглашения в чужую сторону отклоняются.
- **Витрина:** режим «со склада» (`stock`) или «под заказ» (`preorder`: отсечка и дневной лимит), источник — 1С по ключу базы или ручной. Без дня доставки витрину не создать.
- **Статусы заявки:** `draft` → `sent` → `confirmed` / `rejected` / `cancelled` → `assembling` («В производстве») → `shipped` → `accepted` → `closed`. Принять можно и до отметки об отгрузке — досрочно.
- **Заказ в 1С** создаётся при оформлении — «На согласовании» и без проведения. Подтверждение переводит его «К выполнению» и проводит, отказ и отмена снимают проведение. С флажком витрины «Резервировать в 1С сразу» заказ проводится при оформлении. В 1С выгружаются только витрины с источником «1С».
- **Своя база 1С:** адрес (только `https` и публичная сеть), пользователь, пароль — хранится зашифрованным, версия конфигурации и реквизиты заказа из списков самой базы.
- **Минимум в заказе** кратен упаковке: меньше не заказать, и поставщик при подтверждении уменьшает только до него.
- **Приглашения:** ссылка `max.ru/<бот>?start=<код>`; `inv_` — клиент в витрину, `emp_` — менеджер, `wrk_` — работник.
- **Город** у поставщика и у магазина — один, из справочника. «Витрины города» показывают поставщиков города магазина.
- **Телефон** — только российский, по маске «+7 (900) 123-45-67».
- **Тестовые боты** (`app/testbots.py`) — вторая сторона сценария для проверяющих. Ходят в API как люди, с подписью от сервера; id у них отрицательные, в MAX им не пишут.
  - Бот-поставщик держит витрину «Тестовая», её видно в любом городе. Через 15 секунд подключает магазин, который попросился, и подтверждает его заявки.
  - Бот-магазин через 15 секунд просится в новую витрину на тестовой базе из `TEST_BOTS_BASES`, оформляет одну заявку по минимуму, а подтверждённую через 30 секунд принимает досрочно.
  - Картинки «Тестовой» — из витрины аккаунта демо-стенда (`DEMO_MAX_USER_ID`), где их больше всего: логотип, обложка и позиции с фото вместе с названием и ценой. Файлы копируются в хранилище.
  - «Написать» боту присылает карточку аккаунта демо-стенда — человека из команды, без телефона. Остатки боты не пополняют. `TEST_BOTS=0` выключает обоих.

## Правила кода

- Комментарии — по-русски и объясняют «почему», а не «что».
- Тексты интерфейса и ошибок API — по-русски, для человека, кавычки «ёлочки».
- Каждое действие сообщает о загрузке, результате и ошибке — исключения не глотать.
- Демо-контент помечен «Тестовые данные»: этого требует бриф.
- Секретов в репозитории нет: `.env` живёт только на сервере.

## Выкатка

- Пуш в `main` → GitHub Actions (`.github/workflows/runner.yaml`) → раннер на сервере стенда. `build.sh` копирует код в `/opt/max26` и собирает образы, `deploy.sh` поднимает контейнеры, регистрирует вебхук с `message_callback` и проверяет `/health`.
- `.env` с токеном, доменом, секретом вебхука и паролем БД — только на сервере. Пароль БД не менять: том базы создан с ним.
- Caddy ограничивает тело запроса 10 МБ и ставит `nosniff`, HSTS и `Referrer-Policy`. Запрета на фрейм нет: веб-версия MAX открывает приложение во фрейме.

## Особенности MAX

- `user_id` ≠ `chat_id`: чат приходит в `bot_started` и в сообщениях.
- MAX не пишет тому, кто ни разу не открывал бота, — поэтому у записей ленты есть флаг `delivered`.
- API ботов — только `botapi.max.ru`.
- Диплинк не длиннее 128 символов, в `start_param` — только `[\w-]`.
- Кабинет `/1c` работает под CSP без встроенных скриптов: код — в `services/mock-1c/ui.js`, кнопки — через `data-act`.
- API не отказывает по заявленной длине тела: за Caddy ранний ответ рвёт соединение. Отказ — по факту прочитанного.
